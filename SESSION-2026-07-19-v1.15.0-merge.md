## 2. Re-threaded remote-aware lyrics (the v1.14.0 regression)

Done this time (was left open after v1.14.0). Re-wired onto the new
`useSynchronizedLyricsBase` + animation-engine architecture using the **existing**
`use-remote-aware` hooks — no new infrastructure:
- **Click-to-seek → remote**: `use-synchronized-lyrics-base.ts` `handleSeek` routes through
  `useRemoteSeek()` first, falling back to local mpv/media seek. Also makes
  `synchronized-karaoke-lyrics.tsx` remote-aware for free (shared `handleSeek`).
- **Follow remote position/status**: `synchronized-lyrics.tsx` sources the animation engine's
  `currentTimeMs` and play/pause from the hub store (`remotePositionMs` interpolation +
  `remoteIsPlaying`) when `useHubIsRemoteActive()`, via a `useHubStore.subscribe` listener
  mirroring the local status/progress subscriptions. Local playback path is byte-for-byte
  unchanged — the getters short-circuit to the local stores when not remote-active.

**Minor known limitation:** karaoke (word-by-word) *position highlight* still follows the
local timestamp in a remote session (its seek is remote-aware, but its follow reads the local
store). Karaoke-v2 is an upstream feature that never had fork remote-awareness, so this is not
a regression; deferred as out-of-scope polish.
